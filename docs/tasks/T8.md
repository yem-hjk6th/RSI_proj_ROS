# Task T8 (GitHub issue #19)

## Goal
Make `krc_eki_bridge` handle `OverrideCmd.source == "forced"` the way `krc_rsi_bridge` does. In forced open loop, both bridges must then send the same override.

## Background
- **`krc_rsi_bridge`** (`decider.py`, `bridge_node.py` `on_override`):
  - the first message with `source == "forced"` sets a latch that is never cleared until restart;
  - from then on the override ramps linearly from the last value sent to `ov_default` over `fallback_ramp_s`, then holds;
  - later commands do not change it.
- **`krc_eki_bridge`** (#6):
  - `node.py` `_on_cmd` passes only `value_pct` and `seq` to the core; `source` is ignored;
  - so a forced command is applied like any other: a jump instead of a ramp;
  - if the controller restarts, the latch is gone and the bridge follows the controller again.
- `cl_controller` sends `forced` when its speed check latches (`controller.py`, `force_default`).
- This difference was listed as a follow-up in #13.

## Deliverables
- **Forced latch in `krc_eki_bridge`** (`safety.py` / `core.py`, keeping the core's no-blocking rule), with the RSI bridge's semantics:
  - latched by the first `forced` message, never cleared until restart;
  - the output ramps linearly from the last value sent to `ov_default` over `fallback_ramp_s`, then holds;
  - later commands and heartbeats do not interrupt the ramp or end the latch;
  - the clamp still applies to every value.
- Log once when the latch is set, as the RSI bridge does.
- `krc_eki_bridge/README.md`: describe the latch.

## Acceptance tests
1. **Latch.** After `forced`, later `control` commands do not change the output. It ramps to `ov_default` and holds there.
2. **Same as the RSI bridge.**
   - Feed one command and heartbeat timeline to `krc_rsi_bridge.decider.OverrideDecider` (inside the print window) and to the EKI bridge's decision code. The timeline: normal control → forced → more control commands → heartbeat loss.
   - Assert the same override at every step.
   - Where the two cannot be compared (the RSI bridge's print window, step mode), list it in the PR description.
3. **Existing tests.** All green, including `test_bridge_fake_eki.py` and `test_templates.py`.

- Change `krc_rsi_bridge`'s behaviour or `krc_interfaces`.
