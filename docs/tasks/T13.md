# Task T13 (GitHub issue #36): angle-aware readout gates for the fan and semicircle patterns

## Goal
Let the ROS readout nodes read the fan program FAN1 and the semicircle program ARC2: gate the ELP and the borescope
frames by projection on the pattern's lines and rows, with the bore angle cap on the local tangent angle, read the
ELP along the path, and log the geometry of every gated frame. Reproduce the gate decisions the lab logged on
2026-11-03.

## Depends on
T14 (#35, `src/path_geometry`). If T14's PR is not merged when you start, branch from its branch `t14-angle-map` and say
so in the PR description.

## Background
- `legacy/realtime_cl_cage2_semi_261103/README.md`: how `run_cl.py` switches the geometry on, the order of checks and
  the reasons of both gates, the ELP grid, the gate log, and **known issue 2** (the bore cap is tested at the tip).
- Legacy code in the same folder: `fan_geom.py` (`make_fan_bore_gate`, `FanGate`, `frame_rows_dir`), `arc_geom.py`
  (`make_arc_bore_gate`, `ArcGate`, `_ArcReadoutMixin.gate`, `rows_on_grid`, `frame_rows_arc`), `semi_geom.py`
  (`PathLine.grid`, `_SemiInit.gate`, `make_semi_bore_gate`, `_GateLog`), `bore1/bore1_rt.py` (`B1Gate`, `DY_MAX`,
  `X_LO`, `X_HI`, `LAB_BACK`), `bore1/bore2_rt.py`, `rt_readout.py` (grid constants).
- Data: `data/fan1cl_20261103_222754/` and `data/arc2ol_20261103_235936/` (`data/README.md`). Every bore frame the
  bore thread processed is in `bore1_rt` / `bore2_rt` with its `gate` decision; every ELP frame the reader processed
  is in `readout` / `readoutB` (`leg` empty = rejected). Both sessions ran with bore cap 90 deg, so no frame was
  rejected as `angle`.
- In this repository today: `width_readout_elp` reads ELP-A on the straight ±X legs; `width_readout_bore1` gates
  bore1 by x. There is no ELP-B and no bore2 node.

## Deliverables
1. **Gate core** (pure Python, in `path_geometry` or in the two readout packages; no ROS import):
   - `elp_gate(pat, ring, t_frame, kind, lat)` and `bore_gate(pat, ring, t, kind, max_deg, angle_at="tip")` for
     `kind` A and B, with the legacy order of checks, the legacy reason strings and the legacy tolerances;
     `angle_at="obs"` tests |delta| at s_tip − 5 instead (known issue 2), off by default;
   - the path-following ELP grid of a gated tip (fan lines: `FanLines` / `frame_rows_dir`; semi rows:
     `PathLine.grid`), rows at d = 12–25 mm behind the tip, `s_dep` = s_tip − d, MDF band from the line's
     `mdf_side`;
   - the gate log rows (`semi_gate` columns; semi patterns only).
2. **Nodes.** `width_readout_elp` and `width_readout_bore1` use the core when the pattern json has `"geometry"` `fan`
   or `semi`, with the parameters `bore_max_deg` (default 0, as `run_cl.py --fan-bore-max-deg`) and `bore_angle_at`
   (default `tip`). The gate log goes to a CSV next to the other session logs. Every other pattern runs the current
   code unchanged.
3. **Tests** (pytest; CI must pass), including a ROS launch test of each node with a fan pattern by name.

## Acceptance tests
1. All existing golden tests unchanged.
2. **Real-log golden, both sessions, both kinds.** Build the RSI ring from `rsi_data` (`pc_ts_perf`, RIst x, y, z)
   in packet order, as the legacy `RsiRing`. For every logged bore frame and every logged ELP frame:
   - the port equals the legacy gate run offline on the same ring and the same frame time: reason and leg exactly,
     `s_tip`, `s_dep`, `e` within 1e-9 mm;
   - the legacy offline gate equals the live log: same decision and leg, `s_tip` within 0.0005 mm (printed with 3
     decimals). Report the agreement per camera and session in the PR. Every frame where offline and live differ is
     listed with its cause; a difference is acceptable only when it comes from the packets the live ring had at call
     time (state how you emulated that).
3. **Gate log (ARC2-OL).** The port's rows equal `semi_gate_20261103_235936.csv`: cam, leg, row, curv and lobe
   exactly; s and e within 0.0005 mm; delta within 0.01 deg (two printed decimals plus the s rounding); R within
   0.0005 mm.
4. **Angle cap (offline golden).** On both sessions' pose streams, port = legacy for `max_deg` in {0, 10, 15, 30, 45,
   90}, every frame, both kinds. The test shows that `angle` rejections occur.
5. **Grid.** For 1000 gated tips per pattern, the grid points equal the legacy grid within 1e-9 mm.
