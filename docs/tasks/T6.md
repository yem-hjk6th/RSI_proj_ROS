# Task T6 (GitHub issue #11)

## Goal
One launch command starts a print session on the edge PC, the way `legacy/realtime_cl_261023/run_cl.py` does.
- The session is recorded with rosbag2.
- An exporter turns the bag into the legacy CSV logs, so that the existing analysis (`legacy/realtime_cl_261023/eval_v3_print.py`) runs unchanged on ROS sessions.

## Dependency
- `bringup` launches `krc_rsi_bridge` (T1, issue #1).
- If T1 is not on `main` yet, branch from `claude/new-session-6vqcwu`, where T1 has CI green, and rebase onto `main` once T1 is merged.
- Independent of T5: do not create `krc_replay`.
- Both T5 and T6 may touch `src/cl_controller/cl_controller/node.py`. Whoever merges second rebases.

## Deliverables

### Interface additions (a separate, first PR)
The legacy logs hold values that no topic carries today:
- `ov_cmd_<ses>.csv`: the OvCmd actually replied per packet, and its source.
- `ctrl_<ses>.csv`: the controller's internal record per update (`CTRL_COLS` in `run_cl.py`).

Add the messages for them in one small PR first:
- `krc_interfaces`: a per-packet reply record published by `krc_rsi_bridge`, and a per-update controller record published by `cl_controller`.
- Use the field names of the legacy columns where they exist.
- Publishing must not touch the 4 ms reply loop: the bridge publishes from its parent side, from the packet ring, as it already does for `KrcState`.
- This PR must keep every existing test green.

### `src/print_session` (ament_python, new)

**`bringup.launch.py`: the edge stack**
- Runs `krc_rsi_bridge`, `width_readout_elp`, `cl_controller` and the recorder.
- `mode` (`shadow` | `closed` | `step`) is a required launch argument with no default. `run_cl.py` refuses a missing `--mode` since 261020 r2, because a forgotten mode used to mean 1 % override.
- Parameters come from a YAML file; `config/e1.yaml` is the example.

**Camera**
- The camera driver is not in this repository.
- Pick a V4L2 camera driver released for ROS 2 Jazzy. Check that the release exists and document your choice.
- Pass the image topic to the readout as a launch argument.
- Document the encoding and the stamp semantics. The readout needs capture time, not receive time.

**Session metadata**
- Write `session_meta.json` with the same keys as `data/e1_20261022_165128/raw_video/session_meta.json` wherever `legacy/` holds the code that fills them (the `realtime` block: mode, cfg, law, rig, pattern, speed rules).
- `run_cl.py` relies on code that is not in `legacy/`: the `pipeline_cage1012` session flow, the recorder, and camera paths and start / stop rules. List those keys in the PR as not ported. Do not invent them.

**Start-up checks**
- Port the start-up checks and refusals of `run_cl.main` that `cl_controller` and `krc_rsi_bridge` do not already do.
- List each one with its `run_cl.py` line.

**Recording**
- Use rosbag2 to record `/krc/state`, `/krc/override_cmd`, `/width/*` and the two new record topics.
- Choose mcap or sqlite3 and say why.

**Exporter `bag_to_legacy`**
- Turns a bag into `rsi_data_`, `ov_cmd_`, `ctrl_`, `readout_` and `readout_rows_<ses>.csv`.
- Column names and order come from the E1 files and from `CTRL_COLS`, `READOUT_COLS` and `ROWS_COLS` in `run_cl.py`.

## Acceptance tests
1. **Round trip.** Write the E1 CSVs into a bag with a test-only writer, export the bag, and compare: every column must equal the original at the precision the legacy file was written with. Columns the topics cannot carry must be listed, not silently dropped.
2. **Analysis unchanged.**
   - First run `eval_v3_print.py` on the original E1 logs. It must reproduce `roboter/eval_v3_20261022_165128.json`; if it does not, report that and stop this test.
   - Then run it on the exported CSVs. The numbers must be the same.
3. **Bringup smoke test against `krc_sim` on loopback, in shadow mode, for about 10 s.** Check that:
   - the replies carry no OvCmd;
   - a bag is recorded;
   - `session_meta.json` is written;
   - the exporter runs on the bag.
4. **Missing `mode`.** The launch refuses to start.

## Out of scope
- Hardware.
- bore1: its weights are not in this repository and CI has no GPU.
- Camera calibration.
- Any change to the control law or to the bridge's decision logic.
