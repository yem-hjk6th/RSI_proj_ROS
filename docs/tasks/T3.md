# Task T3 (GitHub issue #3)

## Goal
Port the ELP bead-width readout to ROS 2 and check it against the legacy code on real frames.

## Deliverables
- **`src/width_readout_elp`** (ament_python).
  - `width_readout_elp/readout.py`: a port of `legacy/realtime_cl_261023/rt_readout.py`.
    - Includes Rig, Pattern, frame_rows, walk and the frame gates.
    - Pure Python plus numpy/OpenCV. No ROS.
    - Uses `legacy/realtime_cl_261023/rig/*.json`, the occlusion mask, and the R1v30_CLp pattern json.
  - A node:
    - subscribes to `sensor_msgs/Image` and `/krc/state`;
    - keeps a causal RSI ring like the legacy one;
    - publishes `krc_interfaces/Width` on `/width/elp`.
    - The camera and image topics are parameters.
- **A small CLI** that runs the port on a folder of frames plus the RSI log, and writes rows in the legacy `readout_rows` format.

## Acceptance tests (pytest)
1. **Golden frames.**
   - Run the legacy readout on the 40 frames in `data/e1_20261022_165128/elp_frames/`. The frame index is in `raw_video/elp_frames_*.csv.gz`, and the pose comes from `rsi_data_*.csv.gz`.
   - Store the result as a fixture.
   - The port must match it row by row: the same rows present, width within 1e-6 mm.
2. **Online check.**
   - Compare against the online `readout_rows_*.csv.gz` for the same frames, and report the difference.
   - The frames are an MJPEG q95 re-encode, so a small difference is expected. Report it; do not assert zero.
3. **Gates.** On synthetic edge cases, the contrast, coverage and walk-limit gates reject the same rows as legacy.

## Out of scope
- Camera driver selection beyond a parameterised image topic.
