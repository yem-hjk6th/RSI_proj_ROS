# Task T11: bore1 width readout (`width_readout_bore1`)

## Goal
Port the bore1 live width head to ROS 2, so that plan `A_b1` (bore1 -> ELP -> model, the plan of E1) can run. Today
the bringup refuses `A_b1` because nothing publishes `/width/bore1` (`print_session/test/test_bringup.py`).

## Background
- **Legacy code**: `legacy/realtime_cl_261023/bore1/`:
  - `bore1_head.py`: `Bore1Head(weight_dir)`, three frozen ConvNeXt-T seeds, crop and normalisation as in training,
    sha256 check against `weights/weights_sha256.json`, one CUDA graph per frame; `head(frame_bgr)` ->
    `Bore1Pred(w, w_seeds, sd, q_ok, q, ms)`.
  - `bore1_rt.py`: `Bore1Thread` (newest bore1 frame -> gate on the RSI track -> head -> `bore1_rt_<ses>.csv` row
    for every frame -> `RowStore` "bore1" with `d = 5 mm`, `s_dep = s_tip - 5`), `bore1_gate`, `Fusion`.
  - Gate: `|z - z_cmd(x)| < 0.5`, `|y - leg y| < 0.5`, moving -X (`x(t) - x(t - 0.1) < -0.3`), `770 < x < 945`.
    The frame time is the PC receive time; the 5 mm label offset was fitted on it, so no extra latency is added.
  - `requirements_bore1.txt`: torch (CUDA build; RTX 50 series needs the cu128 wheels), timm
    (`convnext_tiny.dinov3_lvd1689m`, `pretrained=False`; the weights come from the `.pt`).
- **Weights are not in this repository** (3 × 111 MB). `weights/` holds the sidecar JSONs and the sha256 list only.
  The lab laptop has the `.pt` files and a GPU.
- **E1 inputs in `data/`**: `raw_video/borescope_frames_*.csv.gz` (frame times), `raw_video/bore1_rt_*.csv.gz`
  (every head output and gate result: `frame,t_frame,t_done,gate,leg,s_tip,s_dep,x,y,z,w,w_s0,w_s1,w_s2,sd,q_ok,
  bright,sat,sharp,diff,ms,pushed`), `roboter/rsi_data_*.csv.gz`. `session_meta.json` `bore1_shadow`: 12878 frames,
  5382 predicted, head time mean 9.5 ms, p95 13.3 ms on the lab laptop.

## Deliverables
- **`src/width_readout_bore1`** (ament_python), core without ROS imports:
  - the gate, the row logic and the `Width` rows as in `bore1_rt.py`;
  - a head interface with two implementations: `torch` (the legacy `Bore1Head`, loaded from a `weight_dir`
    parameter, sha256 checked) and `replay` (returns the logged head outputs of a `bore1_rt` CSV by frame time; for
    tests and offline replays);
  - a node: `sensor_msgs/Image` (`/bore1/image_raw`, from T10) + `/krc/state` -> `krc_interfaces/Width` on
    `/width/bore1`.
- **`krc_interfaces/Bore1Record.msg`**: one per processed frame, the `bore1_rt` CSV row (the head outputs and the
  quality terms that `Width` does not carry). This changes the interface contract: say so in the PR.
- **`print_session`**: start the node for plan `A_b1`; record `/width/bore1*`; `bag_to_legacy` writes
  `raw_video/bore1_rt_<ses>.csv` in the legacy columns.
- **A laptop script** (`test/laptop_golden_bore1.py`, skipped without weights or CUDA): decode the frames of a bore1
  video, run the legacy `Bore1Head` and the port on the same frames, compare.

## Acceptance tests
1. **Golden, CI (no weights).** The legacy `bore1_gate` and row logic on E1's frame times and RSI log, with the
   `replay` head: the port reproduces `gate`, `leg`, `s_tip`, `s_dep`, `x`, `y`, `z`, `pushed` of
   `bore1_rt_*.csv.gz` for every row (floats within 1e-6).
2. **Node, CI.** Lock-step replay of E1 through the node with the `replay` head; the `Width` rows equal the port.
3. **Controller, CI.** E1 through `cl_controller` with plan `A_b1` and the node's `Width` rows reproduces the logged
   override sequence (as `cl_controller` `test_golden_e1.py` does with the logged rows).
4. **Exporter, CI.** bag -> `bore1_rt` CSV, carried columns equal to the original strings.
5. **Laptop (later, not CI).** Real weights, CUDA in WSL: port = legacy head on the same decoded frames (`w` within
   1e-4 mm); head time p95 reported next to the 13.3 ms of E1.

## Out of scope
- Camera capture (T10).
- Retraining or a new head.
