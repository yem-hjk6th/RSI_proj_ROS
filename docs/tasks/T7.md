# Task T7 (GitHub issue #18)

## Goal
Carry the nozzle position of a width reading (`s_tip`) in `Width`, so the controller gets it exactly instead of rebuilding it as `s_mm + d_mm`. Then find out whether T2's two online mismatches (updates 402 and 625) come from this rounding rather than from thread timing.

## Background
- `cl_controller` rebuilds the tip as `s_tip = s_mm + d_mm`. In floating point that is often 1 ulp off the logged `s_tip`.
  - At update 625 a bore1 row sits exactly on the window edge (`s_dep = s_tip − 5`). One ulp moves it out of the window and changes `ov_pub` (#16, "Finding: the node's tip reconstruction").
- `krc_replay` works around this: `session.encode_rows` picks `d_mm` so that `s_mm + d_mm` gives back the logged `s_tip`. 623 rows still come only within one ulp.
- Sending the exact `d` and rebuilding `s` instead changes updates 402 and 625.
  - `src/cl_controller/test/test_golden_e1.py` (b) attributes exactly these two online mismatches to thread timing: a bore1 push reaching the row store a few ms late.
  - They may come from rounding instead, for example of the values written to the logs.

## Deliverables

### `krc_interfaces`
- `Width.msg`: add `float64 s_tip_mm`: the nozzle position along the leg at the frame time, in mm; NaN when the publisher does not know it. Comment it like the other fields.
- `docs/DESIGN.md` §5: add the field.

### Publishers and consumers
- `width_readout_elp` node: fill `s_tip_mm` from the readout.
- `cl_controller` node: use `s_tip_mm` when it is finite; otherwise keep `s_mm + d_mm`.
- `krc_replay` `log_player`:
  - send the logged `s_tip`;
  - send `s_mm` and `d_mm` as logged;
  - remove the `d_mm` adjustment in `session.encode_rows` if it is no longer needed.
- `print_session` exporter: if the readout's `s_tip` column can now be filled, fill it, and update `legacy_cols.NOT_CARRIED` and its test.

### Investigation (report in the PR description)
- Find what makes the port differ from the online run at updates 402 and 625 in `test_golden_e1.py` (b).
  - Candidate 1: rounding of logged values. Check the precision of `s_tip`, `s_dep` and `d` in `readout_rows_*.csv.gz` and `bore1_rt_*.csv.gz`.
  - Candidate 2: the thread-timing explanation in the docstring.
- For each candidate, give numbers: which rows enter or leave the window at those updates, and by how much.
- Change the docstring and `ONLINE_OV_MISMATCH` only if the evidence settles it. If it does not, say so and leave them as they are.
