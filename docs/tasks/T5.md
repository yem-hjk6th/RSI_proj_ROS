# Task T5 (GitHub issue #10)

## Goal
Show that the ROS graph (nodes and topics) gives the same result as the pure-library ports, and that the full real-time chain keeps the safety invariants over a whole recorded session.
- This is the gate before shadow mode on hardware.
- Input: session E1 in `data/e1_20261022_165128/`.

## Dependency
- Needs `krc_sim` and `krc_rsi_bridge` (T1, issue #1).
- If they are not on `main` yet, branch from `claude/new-session-6vqcwu`, where T1 has CI green, and rebase onto `main` once T1 is merged.

## Deliverables

### `src/krc_replay` (ament_python, new)
- **`log_player` node:** publishes a session's logged inputs as ROS messages.
  - `KrcState` from `roboter/rsi_data_<ses>.csv.gz`. Compute `path_speed_mm_s` and `v_eff_mm_s` as the bridge does, reusing `krc_rsi_bridge.path_speed`.
  - `Width` on `/width/elp` from `roboter/readout_rows_<ses>.csv.gz`.
  - `Width` on `/width/bore1` from the rows of `raw_video/bore1_rt_<ses>.csv.gz` with `pushed = 1`.
  - Timing and ordering follow T2's golden replay: `src/cl_controller/test/e1_data.py` and `test/golden/make_e1_fixture.py`.
- **Launch files:**
  - `replay_lockstep.launch.py`: `log_player` + `cl_controller`, deterministic.
  - `replay_realtime.launch.py`:
    - `krc_sim` in replay mode, sending `rsi_data` at 4 ms over loopback UDP;
    - `krc_rsi_bridge` in closed mode;
    - `cl_controller`;
    - `log_player`, publishing only `Width`, keyed to the IPOC the bridge publishes.
  - Parameters come from `config/e1.yaml`.

### Changes elsewhere
- If `cl_controller` needs a hook for deterministic stepping (for example a step-trigger topic), add it behind a parameter. The default must keep today's behaviour. Say so in the PR.
- Leave `krc_interfaces` alone. If you need a new message, propose it in the PR description.

## Acceptance tests
1. **Lock-step equivalence.** Drive the `cl_controller` node through topics with the logged E1 inputs, stepping at the 1719 logged controller update times.
   - The published `OverrideCmd.value_pct` sequence must equal the `ov_pub` column of `src/cl_controller/test/fixtures/e1_legacy_ctrl.csv.gz` exactly.
   - `source` must match that fixture's state / source.
   - Why: T2 showed the library port equals legacy on these inputs. This test shows that the node layer (subscriptions, message conversion, time base) changes nothing.
2. **ELP node under ROS.** Feed the `width_readout_elp` node the 40 frames in `elp_frames/` as `sensor_msgs/Image` (bgr8), together with the logged `KrcState`.
   - The published `Width` messages must equal the rows of `src/width_readout_elp/test/fixtures/golden_legacy_e1.csv`: same frames, legs, s, d, and widths within 1e-6 mm.
   - This is the first time the T3 node runs under ROS.
3. **Real-time chain, short slice (per-push CI).** Choose and document a slice of E1 of at most 60 s that contains the print-window opening and at least one leg start.
   - Assert:
     - `krc_sim` never hits the RSI Timeout;
     - every reply has zero RKorr;
     - every replied OvCmd is within the `config/e1.yaml` window (12..100);
     - the bridge's inside/outside window state per IPOC equals the logged `ov_cmd_<ses>.csv` source (outside vs. the rest).
   - Report, do not assert, the agreement between replied OvCmd and logged `ov_cmd` per IPOC: share identical, and |Δ| median / p95 / max.
4. **Full session (manual CI).** A `workflow_dispatch` job runs the same chain over the whole session (106 897 packets, about 430 s).
   - Same assertions as test 3.
   - Upload the report as an artifact.
   - Keep it out of the per-push CI.
5. **Heartbeat loss.** In the real-time chain, stop `cl_controller` while the window is open.
   - The OvCmd values `krc_sim` receives must ramp linearly to `ov_default` over `fallback_ramp_s`.
   - No RSI Timeout.

## Out of scope
- Hardware.
- bore1 inference.
- Any change to the control law or to the bridge's decision logic.
