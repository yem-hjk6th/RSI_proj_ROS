# Task T4 (GitHub issue #4)

## Goal
Two parts:
1. An EthernetKRL bridge with the same ROS interface as the RSI bridge, for a controller without RSI.
2. Deployment as an edge-PC server and a remote client.

## Deliverables

### `src/krc_eki_bridge` (ament_python)
- Same topics as `krc_rsi_bridge`:
  - publishes `/krc/state` with the fields EKI can provide (unavailable fields are NaN or 0, and documented);
  - subscribes to `/krc/override_cmd`.
- Same safety behaviour: clamp, floor, heartbeat ramp. It never sends motion targets.
- Templates in `src/krc_eki_bridge/krc_templates/`. Every file is headed `NOT RUN`:
  - the EKI XML config (TCP; the port is a parameter);
  - an `sps.sub` user-section snippet that reads the override over EKI without blocking:
    - writes `$OV_PRO` only when `$MODE_OP` is AUT or EXT, and holds the last value otherwise;
    - falls back to a safe default on loss of connection;
    - follows the style of `legacy/krc_config/sps.sub`;
  - a KRL snippet that sends state.
  - Back every KUKA rule you rely on with a public source link, or mark it "unverified".
- An EKI mode in `krc_sim` is welcome but optional. If you skip it, provide a pure-Python fake EKI server for the tests.

### `deploy/`
- `Dockerfile` (`ros:jazzy-ros-base`) that builds the workspace.
- `compose.yaml` with two services:
  - `edge`: host network, `--cap-add=sys_nice`, rtprio/memlock ulimits;
  - `client`.
- A Fast DDS Discovery Server profile, plus notes for `rmw_zenoh`, for a client on Wi-Fi.
- `docs/DEPLOY.md`:
  - edge PC setup (Ubuntu 24.04, low-latency kernel);
  - which links must stay wired (RSI) and which may be wireless (client).

## Acceptance tests
1. pytest against the fake EKI server: state parsing, override send, heartbeat ramp, clamp.
2. CI builds the Docker image (a build-only job is fine).

## Out of scope
- Running anything on a real controller.
- RSI.
