# Task T10 (GitHub issue #26)

## Goal
Capture the cell's cameras in ROS 2, record their video and frame-time CSVs in the legacy formats, and give the
operator a preview. Without this, a ROS print session keeps no video: `print_session` records topics only
(`src/print_session/README.md`, Recording), while every lab print so far stored the ELP and borescope video for the
width dataset and for the post-print checks.

## Background
- **Legacy capture and recording** (reference, read these first):
  - `legacy/pipeline_cage1012/elp.py` (`ElpCam`: MJPG capture, controls, read-back, MJPG AVI writer, frame CSV);
  - `legacy/realtime_cl_261023/elp_hevc.py` (the ELP recorder of 2026-10-23: raw BGR into an `ffmpeg` subprocess,
    `hevc_nvenc -preset p4 -tune hq -rc vbr -cq 18 -b:v 0`, full range, `bt470bg` / `smpte170m` tags, fragmented MP4,
    one file per segment, fallback to the MJPG AVI writer, ring-delayed CSV commit so CSV rows and file frames stay 1:1);
  - `legacy/pipeline_cage1012/borescope.py` (`BoreScope`: 1280×720, mp4v, never sets exposure);
  - `legacy/pipeline_cage1012/config.py` (camera profiles, segment lengths).
- **What E1 ran with** (`data/e1_20261022_165128/raw_video/session_meta.json`):
  - ELP: MJPG 1920×1200 requested at 60 fps, measured 78.4 fps; `CAP_PROP_AUTO_EXPOSURE` 0.25 (manual),
    `CAP_PROP_EXPOSURE` -7 (DirectShow: 2^-7 s = 7.81 ms), gain 0, auto WB off, WB 4600 K; stored raw (no rotation);
    1-minute segments.
  - Borescope: 1280×720, nominal 30 fps, mp4v, 15-minute segments.
- **Frame CSV columns** (both cameras, E1 files under `data/e1_20261022_165128/raw_video/`):
  `pc_ts_monotonic,pc_ts_wall,frame_idx,segment_idx,frame_in_segment,video_file,pc_ts_perf`.
  File names: `elp_<ses>_<seg:03d>_<segment start>.mp4`, `bore_<ses>_<seg:03d>_<segment start>.mp4`,
  `elp_frames_<ses>.csv`, `borescope_frames_<ses>.csv`.
- **The cage** (2026-10-27 on): two ELP cameras (A and B sides) and two borescopes. Which of them a session uses is a
  lab choice, so the set of cameras is a parameter.
- **Lab laptop facts** (`docs/deploy_wsl.md` §7): `hevc_nvenc` works in WSL; the ROS graph needs
  `FASTDDS_BUILTIN_TRANSPORTS=SHM`.
- **Throughput.** A raw 1920×1200 `rgb8` image is 6.9 MB; at 78 fps that is about 540 MB/s per subscriber. The
  legacy pipeline captured, recorded and read out in one process (threads). Two extra Python subscribers of the raw
  stream are a risk to the frame rate.

## Deliverables
- **`src/camera_capture`** (ament_python), core without ROS imports:
  - One node per camera: open by a stable Linux device path (`/dev/v4l/by-id/...` or `/dev/v4l/by-path/...`), set
    the format and the V4L2 controls from parameters, **read every control back** and log requested and read-back
    values (as `ElpCam` does).
  - Record in the same process as the capture: the ELP through `ffmpeg` `hevc_nvenc` with the legacy settings and
    the legacy fallback; borescopes as mp4. Frame CSVs in the legacy columns, 1:1 with the frames in the files.
  - Publish `sensor_msgs/Image` for the readouts (`/elp/image_raw`, `/bore1/image_raw`, ...), stamped with the
    capture time on the clock of `KrcState.stamp`, and a decimated preview topic (5 Hz, downscaled).
  - Choose between this in-process design and a separate recorder node only with a measured frame rate on the lab
    laptop; state the choice and the numbers in the PR.
- **Preview**: one window with the cameras' preview topics tiled 2×2 (the legacy `quad_preview.py` layout: pair 1 on
  the left), off the control path.
- **`print_session` integration**: a `cameras` parameter file for the bringup (replaces `start_camera` /
  `camera_params` for the new node, keep `usb_cam` as an option), files written to `<session>/raw_video/`, and a
  `session_meta.json` camera block like the legacy one (`requested`, `readback`, `measured`: frames, dropped, fps,
  segments, encoder, fallback).
- **Example parameters** with placeholders (device paths). The ELP exposure in V4L2 units: `exposure_time_absolute`
  is in 100 µs, so 7.81 ms is 78 (computed, to be checked on the camera against a legacy frame).

## Acceptance tests (pytest, no camera)
1. A fake capture source (frames from a file or synthetic) through the recorder: segment files and CSV rows 1:1
   (count the frames in each fragmented MP4, as `elp_hevc.fmp4_frames` does).
2. CSV header and file names equal the E1 files.
3. No `ffmpeg` or no NVENC: the fallback writer takes over, logged, CSV and files still 1:1.
4. `ffmpeg` killed mid-segment: rows and frames stay 1:1, lost frames counted, as in `elp_hevc.py`.
5. Preview decimation and image stamps (monotonic, capture time).
6. CI has no GPU: the NVENC path is tested with a stub; a `hevc_nvenc` test that skips without a GPU.

## Hardware checks for the lab (written into the PR, run later on the laptop)
- `v4l2-ctl --list-formats-ext` and `--list-ctrls` for each camera; the device-path-to-camera mapping.
- 10 min at the ELP's native rate: dropped frames 0, CSV rows = file frames, CPU load, NVENC in use.
- Exposure: a frame next to a legacy frame of the same scene (same light), mean intensity within a stated tolerance.

## Out of scope
