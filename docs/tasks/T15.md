# Task T15 (GitHub issue #38): cage 2 — ELP-B and bore2 width nodes, bore-led source selection (plan A_b1, bore2 primary)

## Goal
Port the cage-2 parts of the lab pipeline so that the bore-dual closed loop of 2026-11-03 on the single-layer CLp4
program runs through the ROS graph. Cage 2 has a second ELP camera (ELP-B, reading the +X lines) and a second
borescope (bore2, also on +X). On the −X legs bore1 steers first, then ELP-A, then the model. On the +X lines a
second law (law B) is steered by bore2, then ELP-B, then the model. Reproduce the session logged that evening.

## Depends on
T13 (#36) merged. Branch from the current `main`.

## Deliverables
1. **ELP-B readout.** `width_readout_elp` gets a kind-B mode, or a second node of the same package: the B lines,
   motion along +X, the grid behind the tip on the +X side, the MDF band side as a parameter (`b_mdf_side`, default
   `pos`), and its own topic and rig. Kind A behaves as now.
2. **bore2 readout.** `width_readout_bore1` gets a `camera` parameter (`bore1` | `bore2`), or a sibling package:
   - the bore2 crop (544, 1120, 0, 576) and the horizontal flip;
   - `bore2_gate` (frame time, no latency, +X motion, the pattern's x window, reason `line_or_x`), `s_dep` = s_tip − 5;
   - the bore record columns; the replay head for CI, as T11 has;
   - a laptop script that skips when there are no weights or no CUDA.
3. **Controller** (`cl_controller`):
   - the cage-2 `CtrlCfg` fields (`elp_b`, `b_from_leg`, `dir_win_s`, `dir_vmin`, `bore2` = off | shadow | fallback |
     primary, `bore_s_use`) and the `w_offset` / `bore_sd_max` inputs;
   - `_where2` / `_slot` / `_update_ab`: law A on −X legs, law B on +X lines from `b_from_leg`, u carried across
     each handover;
   - `RowStoreB` with `veff_at_s(x_sign=+1)`;
   - the new ctrl columns (`law`, `kind`, `dir`, `vx`, `src_active`, `src_why`) and the switch record;
   - every start refusal of the legacy `run_cl.py` that concerns these flags.
   - Reproduce the legacy law B source order exactly (bore2 → ELP-B → model, G4 on, `blind_tau` 0, sources fixed).
     The legacy law B ignores `control_sources`; say so in the PR rather than changing it.
4. **Bringup**: `print_session` launches ELP-B and bore2 (cameras and readouts) when cage 2 is selected.
   - Bind each rig to a role (ELP-A, ELP-B), not to a USB instance id: on 2026-11-03 the same id appears as ELP-A in
     the lab notes and as ELP-B in a rig comment.
5. If `krc_interfaces` changes, say in the PR that the interface contract changes.

## Acceptance tests
1. All existing golden tests unchanged; with `elp_b` off and `bore2` off everything behaves as now.
2. **Real-log golden (`data/bduo_20261103_195120/`).**
   - ELP-B gate: every frame in `readoutB_*`. Port equals legacy run offline on the same RSI ring (exactly). Legacy
     offline equals the live log (decision and leg exactly, `s_tip` within 0.001 mm).
   - bore2 gate: every frame in `bore2_rt_*`. Port equals legacy offline (exactly). Legacy offline matches the live
     log at the ring cut `t_done` (reason and leg exactly, `s_tip` within 0.1 mm). Every larger difference must be
     matched by an earlier cut; T13 measured this behaviour on the fan / semi gates.
   - Controller: feed the logged ELP-A / ELP-B rows, the pushed bore1 / bore2 rows and the RSI stream, in time order,
     to the legacy controller with the session's flags (`session_meta.json` → `realtime`) and to the port.
     - Port = legacy on OvCmd per step and per packet, source, `law`, `kind`, `src_active` and the switch records
       (floats within 1e-9).
     - Legacy replay vs the live `ctrl` / `ov_cmd` / `switch` logs: report the agreement and explain every
       difference.
3. **Refusals**: one test per refusal.
4. **Safety**: law B's OvCmd goes through the same clamp, speed floor, watchdog ramp and forced latch as law A
   (tests on both laws). RKorr stays 0.
