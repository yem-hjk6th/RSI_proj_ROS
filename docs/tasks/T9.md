# Task T9 (GitHub issue #20)

## Goal
Make the repository ready for its first hardware test and for readers of the paper:
- documentation that matches the merged packages;
- a deployment guide for WSL 2 on a Windows 11 lab PC;
- a one-command network latency test;
- a clear warning about shadow mode on the `RSI_OV4` program.

Nothing in this task runs on hardware.

## Background
- **Docs are behind the code.**
  - The root `README.md` and `docs/DESIGN.md` were written before T1–T6.
  - `CtrlRecord` and `ReplyRecord`, `print_session` and `krc_replay` are not in `DESIGN.md` §4–§5 (noted in #14 and #15).
- **The planned edge PC is the Windows 11 lab laptop**, with the ROS stack in WSL 2. The controller then needs no change, because WSL in mirrored networking mode shares the laptop's IP address.
- **Shadow mode on `RSI_OV4` means 1 % override.**
  - In shadow mode the bridge's reply carries no `<OvCmd>`. Under `RSI_OV4` the OvCmd input is then 0, and `LIMIT1` (1..100) raises it to 1.
  - `legacy/realtime_cl_261023/run_cl.py` lines 4 and 7 record the same.
  - The print program loads `RSI_OV4` (`RSI_CREATE("RSI_OV4.rsi")`). See `legacy/README.md` once the PR that adds `RSI_OV4` to `legacy/` is merged.
  - So shadow mode needs a print program on `RSI_MIN`.

### `docs/deploy_wsl.md` (new)
Mark the whole guide as untested on hardware. Cite the Microsoft pages it relies on. Give the expected reading for each check. It covers:
- **Distribution.** Ubuntu 24.04 in WSL 2 for Jazzy, or Docker inside WSL with `ros:jazzy-ros-base`.
- **Networking.**
  - `.wslconfig` with `[wsl2] networkingMode=mirrored` (Windows 11 22H2 or later).
  - A Hyper-V firewall inbound rule for the RSI UDP port, using `New-NetFirewallHyperVRule` with the WSL VM creator ID. Microsoft's example is TCP; state that the UDP rule is the same command with `-Protocol UDP`.
  - Why the default NAT mode cannot work: `netsh interface portproxy` forwards TCP only.
- **ELP camera.**
  - `usbipd bind` / `usbipd attach --wsl`, then `modprobe uvcvideo` and `v4l2-ctl --list-devices`.
  - `usb_cam` with `config/elp_usb_cam.yaml`.
  - Checks: frame rate, dropped frames, stamp delay.
- **What cannot run at the same time:**
  - the Windows pipeline and the ROS stack (in mirrored mode they share ports);
  - the camera on Windows and in WSL.

### Latency test
- One command (a launch file or a CLI in `krc_replay` or `krc_sim`) that runs `krc_sim` against a bridge on another host (`host`, `port`) for a given time.
- It prints:
  - packets sent;
  - late replies and the longest run of them;
  - Timeout yes or no;
  - round-trip time p50 / p99 / max;
  - replies with nonzero RKorr;
  - OvCmd outside the window.
- Reuse `krc_replay.report` where it fits.
- The bridge side runs `krc_rsi_bridge` alone, in closed mode, with `config/e1.yaml`.
- Document both sides in `deploy_wsl.md`.
- Test it on loopback in CI, with a short run (≤ 20 s).

### Shadow-mode warning
- `print_session`: in shadow mode, log a warning at start-up. It says that the reply carries no OvCmd, and that on a program using `RSI_OV4` the robot runs at 1 % override.
- Say the same in `print_session/README.md`, the root `README.md` and `deploy_wsl.md`.
- If you think shadow mode should instead be refused unless a parameter confirms an `RSI_MIN` program, propose it in the PR description. Do not implement it.
